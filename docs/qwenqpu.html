Qwen runs quantum circuits in its own weights

qwenQPU · built on the Qwenputer compiler · Qwen3.5-4B

We took a stock Qwen3.5-4B and put 16 extra layers in front of its own 32. Nobody trained those layers. A compiler set every weight, and together they form a small quantum computer simulator: up to five qubits, exact arithmetic, and measurements sampled by the model itself.

When Qwen needs a circuit simulated, it writes OpenQASM in an ordinary tool call. A thin host program translates the gate names into instruction words and hands them back to the model. From there the model writes out every amplitude of every gate as a token, and the final state matches Qiskit's statevector exactly, with no rounding anywhere.

This is a classical simulation. A register of n qubits has 2n amplitudes, each gate here costs 2n tokens, and nothing gets faster than a laptop running Qiskit. So why build it? Because it shows that a language model can carry an exact, checkable machine inside its own forward pass. The idea comes from Qwenputer, which compiled a RISC-V CPU into Qwen's weights, and qwenGPU, which did the same for a small CUDA GPU. We wanted to see whether the trick survives a machine whose state is a vector of amplitudes.

A memory made of attention state

Qwen3.5 interleaves ordinary attention with Gated DeltaNet layers. A DeltaNet head doesn't keep a growing cache of past tokens. It keeps one fixed 128×128 matrix and updates it at every token with the delta rule. Read the rule with two special inputs and something useful falls out. If the key is one-hot, pointing at row r, the update replaces row r with the value vector and leaves every other row alone. If the query is one-hot, the head returns row r. That is a RAM with 128 addressable cells per head.

Qwenputer found this and used it for a CPU's registers and memory. We use it for the quantum state: one row per basis state, holding that amplitude as 16 bits. A three-qubit state is eight rows.

A gate is a burst of tokens

A forward pass has fixed depth, so it can't loop over 32 amplitudes. The loop has to happen in the token stream instead. Applying a Hadamard to qubit q pairs up amplitudes whose index differs only in bit q, and each pair becomes (a0+a1, a0−a1). The model walks those pairs and emits each new amplitude as one token. Each 16-bit token comes from a single forward pass, which does four things:

It counts how many values it has written since the GATE token, which tells it which amplitude is due. It reads that amplitude and its partner from memory. It adds or subtracts them. Then it writes the result's bits into the output so that the next token's id is the result. When that token is fed back in, the memory heads store it. The model's sampling loop becomes the machine's clock.

The arithmetic is less exotic than it sounds. With the right scaling, a SwiGLU unit computes a·relu(b) exactly. For an integer z, relu(z−θ+1) − relu(z−θ) is 1 when z ≥ θ and 0 otherwise, so two units make an exact step function. Enough steps give you "bit 3 of this 5-bit sum", and two MLP layers of those make a carry-lookahead adder for 16 bits. The output side works the same way in reverse. The last layer writes the 17 bits of the token id it wants into a few dimensions that the language-model head reads, so that token wins the argmax by a wide margin.

Reading old values while writing new ones

Writing in place breaks the walk. The new a0 overwrites the old a0, but the very next token, the new a1, still needs it. So the machine keeps two copies of the state and alternates them. Gate g reads buffer g mod 2 and writes the other one, so every value is computed from the state as it stood before the gate.

Each buffer is also stored twice, because a head answers only one query per token and every value needs two amplitudes, its own and its partner's. With the complex mode described below, that comes to 16 memory heads in a single layer. A Qwen3.5-4B layer has exactly 16, so the layout just fits.

Why the answers are exact

The model runs in bf16, which keeps only 8 significant bits. The compiler copes by never letting a value get large. Everything inside the circuit is a bit, a one-hot vector or an integer up to 256, and Qwenputer's evaluator checks every intermediate against bf16 rounding before a single weight is written.

That rules out floating-point amplitudes, so the machine doesn't use them. It stores integers and keeps one shared scale, 1/√2k. A Hadamard adds or subtracts and bumps k. X, CNOT and Toffoli move amplitudes around. Z flips a sign. None of these ever produce a fraction.

Phases need one more idea. With S and T gates the amplitudes live in the ring of integers over ω = eiπ/4, so each amplitude becomes four integers, a0 + a1ω + a2ω2 + a3ω3. Multiplying by ω then needs no multiplier at all. It shifts the four integers one place and negates the one that wraps around, because ω4 = −1. That covers the 3-qubit QFT and phase estimation of the T gate, which reads out exactly 001, i.e. 1/8.

The cost of exactness is a fixed gate set. Rotations by arbitrary angles such as rz(0.3) fall outside this ring and would need approximating with sequences of H and T. Complex circuits also carry four tokens per amplitude, so that mode stops at four qubits.

Measuring with the model's own dice

A real quantum computer returns samples, not amplitudes, and a language model happens to come with a sampler. The trick is ties. If the circuit leaves an output bit undecided, the two tokens that differ only in that bit get bit-identical logits, and any sampler picks between them with probability exactly ½, at any temperature. Leave m bits open and you get a uniform random m-bit number.

Turning fair coins into the Born rule, P(i) ∝ |ai|2, is a rejection sampler. The model draws a random basis state i and two random numbers u1, u2 below 2m. It accepts i if both numbers fall below |ai|. The chance of that is (|ai| / 2m)2, which is proportional to |ai|2, so accepted states follow the Born distribution exactly. The circuit never multiplies anything. It takes an absolute value and does two comparisons.

Does Qwen use it well?

We asked Qwen3.5-4B 22 questions about circuits, each with one exact probability as the answer. Every circuit the model ran on its QPU was token-exact against the reference: 19 runs and 9,107 model-written tokens, with no mistakes. Merging the QPU barely touches Qwen's text: the KL divergence from the base model's next-token distribution is 4.8×10−4, and the top token agreed at all 50 positions we checked.

The split tells the story. Given an explicit gate sequence, Qwen copies it into QASM correctly every time and the QPU does the rest. Asked to build Grover, Deutsch–Jozsa, a QFT or phase estimation from the name alone, the 4B model writes a wrong circuit or runs out of tokens explaining it, and the QPU then answers the wrong question exactly. We checked that the machine isn't the bottleneck by putting a host-side simulator behind the same tool in an earlier run: it scored 13 of 16 where the QPU scored 12. The difference is Qwen's own text drifting slightly between the two runs, not the QPU.

Limits

Size5 qubits with real gates; 4 with S, T and phases.
GatesH, X, Y, Z, S, T and their inverses, any of them (except H) with controls. No arbitrary rotation angles. About 28 Hadamards per circuit before 16-bit amplitudes could overflow.
SpeedOne token per amplitude per gate, four with phases. A 3-qubit Grover search is 316 tokens (23 s); phase estimation is about 1,000 (77 s). That is with a plain Hugging Face decoding loop at ~14 tokens/s, nothing optimized.
FootprintQwen's hidden size grows from 2560 to 3200, about 16 GB in bf16. Qwenputer's trick of sharing Qwen's own dimensions would shrink that; we haven't applied it yet.

What made it work

  1. State lives in recurrent memory, loops live in the token stream, and a forward pass only does fixed-depth arithmetic. That division is what lets a transformer run an algorithm of any length.
  2. Pick a number system the hardware can't round. Bits, small integers and the ring Z[ω] keep every value exact in bf16. Floats would have made exact matching against Qiskit impossible.
  3. Each generated token is one 16-bit write. The token id carries the data, so the machine's trace is the model's output and anyone can replay it.
  4. The host translates, the model computes. The host turns QASM into instruction words and reads the result back. Every value in between comes from the weights and is checked token by token against a reference.
  5. The sampler is hardware too. Exactly tied logits are fair coins, and fair coins plus comparisons give exact Born-rule sampling.
